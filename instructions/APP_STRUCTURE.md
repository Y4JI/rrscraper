# rrscraper - Django Application Structure

This document outlines the directory and file structure of the `rrscraper` Django application.

## Root Directory (`c:\Users\MyPC\3RDYR-CS\rrscraper\`)
This is the root of your project workspace.

- **`db.sqlite3`**: The default SQLite database file used by Django. It stores all your application's local data.
- **`manage.py`**: A command-line utility that lets you interact with this Django project (e.g., run the server, apply database migrations, create superusers).
- **`project/`**: The main configuration directory for your Django project.
- **`scraper/`**: The directory for your specific Django app where the main application logic, views, templates, and models are stored.
- **`venv/`**: Your Python virtual environment folder, which contains the installed dependencies for the project.

---

## The `project/` Directory
This folder contains the core settings and routing for the entire project.

- **`__init__.py`**: An empty file that tells Python that this directory should be considered a Python package.
- **`settings.py`**: The main configuration file for the Django project. It contains settings for database connections, installed apps, middleware, static files, and more.
- **`urls.py`**: The root URL declarations for the project. It routes incoming HTTP requests to the appropriate app's `urls.py` or views.
- **`wsgi.py` / `asgi.py`**: Entry points for WSGI-compatible or ASGI-compatible web servers to serve your project in production.

---

## The `scraper/` Directory
This folder represents the "scraper" application, which contains the actual logic for web scraping, user interaction, and data presentation.

- **`__init__.py`**: Marks the directory as a Python package.
- **`admin.py`**: Configuration for the Django built-in admin interface. You can register your models here to view and manage them via the admin panel.
- **`apps.py`**: Application-specific configuration for the `scraper` app.
- **`models.py`**: Defines the data models (database schemas) for the app. Each class typically maps to a single database table.
- **`urls.py`**: App-specific URL declarations. It maps URLs like `/login`, `/register`, or `/home` to the corresponding functions in `views.py`.
- **`views.py`**: Contains the main business logic. Views handle incoming HTTP requests, process data (like fetching from the database or running scraping logic), and return HTTP responses (usually rendering HTML templates).
- **`tests.py`**: A place to write automated tests for the app.
- **`migrations/`**: A directory that stores database migration files generated by Django. These track changes made to your `models.py`.

### `scraper/templates/scraper/`
This directory holds the HTML files that dictate the structure of your web pages.
- **`base.html`**: The base HTML template. It usually contains the common structure (header, footer, navigation) that other templates inherit from.
- **`home.html`**: The template for the home page.
- **`login.html`**: The template for the user login page.
- **`register.html`**: The template for user registration.

### `scraper/static/scraper/`
This directory holds static assets like CSS, JavaScript, and images that are served directly to the user's browser.
- **`style.css`**: The main stylesheet used to define the visual appearance and layout of your HTML templates.
